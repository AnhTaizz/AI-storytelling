HOW TO READ A FINDING
- phase and code name the stage and the rule that rejected the draft. rule_class says
  the same thing in words.
- record_locator says how the finding points at a record of the primary response.
  VERIFIED_UNIQUE_RECORD: record_collection, record_index and record_handle name one
  record. record_index counts from 0 within that collection. The host verified that
  exactly one record of that collection has that handle and that it is at that index.
  SCHEMA_PATH_INDEX: the record has no handle the host could verify. Its position is
  the number after the collection in schema_path.
  NOT_RECORD_SCOPED: the finding is about the whole response or a whole check.
  UNAVAILABLE: the finding is about one record and the host could not verify which.
  record_index and record_handle are null whenever the locator is not
  VERIFIED_UNIQUE_RECORD. The host never guesses a record.
- schema_path points further inside the record. <UNVERIFIED> stands for a part the host
  could not verify.
- validator_check and validator_section name the canonical validator check, when the
  finding comes from canonical conformance.
- structural_detail holds counts, registry values and verified handles. It never holds
  story text and never states what the story content should be.
- source says who found the problem. FROZEN_COMPILER_BLOCKER is the compiler's own
  rejection. INDEPENDENT_REGISTRY_CHECK is the host applying the same registry rule to
  your draft directly. When compiler_reached is false, the compiler stopped at an
  earlier finding and would have rejected this one next. Correct it as well.
- repairable_by_model false marks a failure on the host side. You cannot correct it.
  Do not change the draft because of it.
- Every finding is a separate problem. Correct all of them.

HOW TO READ COMPLETENESS
- completeness holds separate statements. complete is true only when all of them are
  true. It is false for every rejected draft, so read the statements.
- observed_blockers_preserved: there is one finding for every blocker the host saw.
- observed_blockers_located: every finding about one record names that record.
- observed_blockers_attributed: every finding names a rule the host recognizes.
- compiler_structural_rules_checked: the compiler checked quotes, handles and registry
  names. When false, it stopped earlier and those rules are still unchecked.
- canonical_validation_reached: the canonical validator ran. When false, the compiler
  stopped earlier and the canonical rules are still unchecked by it.
- downstream_canonical_issues_enumerated: every canonical issue is listed. This is
  false for every rejected draft. The host lists the canonical issues it can check
  itself and cannot list the rest.
- independent_checks_consistent_with_compiler: no host check contradicted the compiler.
- limitations names what the host could not tell you.
- The findings are therefore what the host saw, not everything that may be wrong.
  After correcting them, re-check the whole draft against the three COMPILER RULE
  sections.

RULES BY CODE
- AMBIGUOUS_QUOTE: the quote of that record occurs more than once in its passage and the
  record has no occurrence. exact_match_count is the number of exact matches. Add
  occurrence with the 1-based index of the match the record refers to, between
  valid_occurrence_minimum and valid_occurrence_maximum. Decide which match from the
  passage. The host does not know which one you mean and no default is correct.
- QUOTE_NOT_FOUND: the quote is not an exact substring of its passage. Copy it from the
  passage code point for code point.
- OCCURRENCE_OUT_OF_RANGE: occurrence is larger than exact_match_count.
- UNKNOWN_PASSAGE_HANDLE and CONTEXT_ONLY_EVIDENCE: the record cites a passage that was
  not supplied, or one that is not EVIDENCE_ELIGIBLE.
- UNKNOWN_HANDLE, HANDLE_TYPE_MISMATCH and PRIOR_CONTEXT_NOT_EVIDENCE: a handle at
  schema_path does not exist, has the wrong record type, or is not evidence declared in
  this draft.
- DUPLICATE_HANDLE: records_sharing_this_handle records of record_collection use the
  same handle. A shared handle names no single record, so the host shows no handle and
  no index. Find the records of that collection that share a handle, give each its own
  handle, and make every reference cite the record it means.
- UNREGISTERED_PREDICATE, UNREGISTERED_EVENT_KIND and UNREGISTERED_RULE: the value at
  schema_path is not in the predicate registry.
- ARGUMENT_ENTITY_KIND_NOT_ALLOWED: in the proposition named by the finding, the entity
  referenced by argument has kind referenced_entity_kind, and the registry allows only
  allowed_entity_kinds for that argument of that predicate. The registry constraint is
  fixed. The host does not say which record is wrong.
- RULE_CANNOT_CONCLUDE_PREDICATE: in the assertion named by the finding, the derivation
  at derivation_index uses rule_id, and that rule may conclude only
  allowed_conclusion_predicates. The assertion's proposition uses a different predicate.
