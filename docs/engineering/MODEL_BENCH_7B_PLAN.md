# Phase 7B · Owner approval template

Review the draft gold and rubrics in `data/model_bench_dev/v1/` before approving measurements. Generate the approval table from the exact revision, model, case selection and output reserve that will be used for the run.

```powershell
python -m tools.model_bench.run --provider groq --model openai/gpt-oss-20b --group event_extraction --limit 3 --dry-run --plan-md
```

Paste the generated table and fingerprint into the approval record.

| Model | Group | Cases per repeat | Requests | Est. input + reserved output | Quota limit | Days ≥ |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| Generated by the dry run | | | | | | |

Record the owner name, actual quota scope, current available RPM/TPM and daily allowance, repeat dates, case batches and human reviewer. Use at least three independent repeats per model and task group. Each invocation executes one repeat. Use a fresh run directory for each repeat and use `--resume` for an interrupted repeat. When splitting a repeat across quota windows, generate and approve a fingerprint for each case batch. Pace and size each batch against confirmed actual quotas, including allowance for provider retries. The table estimates one dispatch per case and its days are lower bounds based on known daily quota. The provider adapters may retry within the transport budget printed by the dry-run table.

A live run may start only after the owner confirms M9 is outside the same provider quota for that batch. Reconfirm before starting or resuming. Phase 7A does not inspect M9 state. OpenRouter's `openrouter/free` selector can choose different models, so use a named `:free` model for a pinned run. Provider settings come from the process environment and the benchmark uses its own quota ledger under `.local/model_bench_runs/`.

Save approval as a private UTF-8 JSON file. Replace the placeholders only after the owner has approved the table and cleared the quota window.

```json
{
  "plan_sha256": "<fingerprint from the generated table>",
  "approved_by": "<Project Owner>",
  "m9_quota_clear": true
}
```

Use the same dry-run arguments, omit `--dry-run --plan-md` and add `--live --approved-plan <file>`. A changed fingerprint requires renewed approval. An interrupted live case whose dispatch status is uncertain requires reconciliation before resuming. A stale `run.lock` can be removed after confirming the process has stopped. Keep checkpoints and provider credentials private.

Record completion and efficiency per repeat, then compare the deterministic scores and dispersion across repeats. Use `human_review.jsonl` to grade each narrative plan and Vietnamese script against its rubric and evidence. Machine scores cover the deterministic groups.
